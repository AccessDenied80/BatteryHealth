# BatteryHealth — дизайн

Дата: 2026-11-01 · Автор: AccessDenied80 · Сестринський проєкт: [DiskHealth](https://github.com/AccessDenied80/DiskHealth)

## Навіщо

Користувач хоче в одному місці бачити стан **усіх** своїх акумуляторів: знос батареї MacBook (щоб вчасно
замінити) і заряд бездротових пристроїв та iPhone, і **отримувати попередження**. Застосунок має бути
«схожим на DiskHealth» — той самий підхід, вигляд, локалізація й спосіб публікації.

## Цілі

- Нативний застосунок у рядку меню macOS (Swift/SwiftUI), окремий від DiskHealth.
- **Батарея Mac** (повні дані, IOKit `AppleSmartBattery` + `IOPSCopyPowerSourcesInfo`):
  здоров'я % (`AppleRawMaxCapacity / DesignCapacity`), цикли / розрахункові цикли (`CycleCount` / `DesignCycleCount9C`),
  поточна й заводська ємність (мА·год), заряд %, температура, напруга загальна та по комірках (`BatteryData.CellVoltage`),
  сила струму, заряджається / від мережі / повністю заряджена, стан від macOS (`BatteryHealth`, «Service Recommended»),
  дані блока живлення (назва, Вт), `PermanentFailureStatus`.
- **Периферія** (лише рівень заряду, без зносу):
  - Apple Magic Mouse / Keyboard / Trackpad — IOKit-сервіси з властивістю `BatteryPercent`;
  - AirPods та інші пристрої, для яких macOS знає заряд — `system_profiler SPBluetoothDataType -json`
    (поля `device_batteryLevelLeft/Right/Case/Main`);
  - ігрові контролери — `GameController` (`GCController.battery`).
  - Пристрої, для яких macOS заряду не знає, показуються як «підключено, заряд невідомий» або не показуються.
- **iPhone** (через USB або Wi-Fi-синхронізацію, без root) — приватний `MobileDevice.framework`:
  заряд і стан заряджання (lockdown-домен `com.apple.mobile.battery`), а за можливості — цикли та
  ємність через `com.apple.mobile.diagnostics_relay` (IORegistry `AppleSmartBattery`). Умова: iPhone довірив цьому Mac.
- **Сповіщення** (один раз на подію, як у DiskHealth):
  - здоров'я батареї Mac < порогу (за замовчуванням 80%);
  - macOS позначила батарею «Рекомендовано обслуговування» або `PermanentFailureStatus ≠ 0` — критично;
  - температура батареї Mac ≥ 45 °C;
  - заряд периферії / iPhone ≤ 15% (повторно — лише після заряджання вище 25%);
  - здоров'я батареї iPhone < 80%.
- **Історія** (365 днів): здоров'я та цикли Mac (і iPhone, якщо доступно), графіки в деталях.
- Опитування: батарея Mac — миттєво за подією IOPS (зміна джерела живлення) + кожні 5 хв;
  периферія — кожні 5 хв; iPhone — кожні 30 хв і при підключенні.
- Інтерфейс англійською й українською (за мовою macOS), налаштування порогів, «Запускати при вході».

## Не-цілі

- Керування зарядкою (обмеження до 80% тощо) — потребує root і запису в SMC.
- Apple Watch — заряд з Mac офіційно й неофіційно без root недоступний.
- Нотаризація / Mac App Store (як і DiskHealth: ad-hoc підпис, GitHub Releases).
- Bluetooth-пристрої, яких macOS не знає (без власної BLE-взаємодії з ними).

## Анти-цілі

- Будь-які запити пароля адміністратора чи привілейовані помічники.
- Хибні тривоги про низький заряд, що повторюються щохвилини.
- Помітне навантаження на батарею від самого моніторингу (часте `system_profiler` тощо).

## Обмеження та рішення

- **Без додаткових прав** (рішення користувача): лише те, що доступне звичайному користувачу.
- Архітектура як у DiskHealth (рішення Claude): SwiftPM-пакет `BatteryHealthCore` (моделі, парсинг словників
  IOKit / JSON system_profiler, оцінка стану, рушій сповіщень, історія — з тестами на зразках реальних даних)
  + `BatteryHealth` (SwiftUI MenuBarExtra, джерела даних, сповіщення). Скрипти `test.sh`, `build-app.sh --dmg`,
  `make-icon.swift`, режим `--snapshot`. Universal-збірка, macOS 13+.
- Bundle id `io.github.accessdenied80.BatteryHealth`, ліцензія MIT, репо `AccessDenied80/BatteryHealth`.
- **iPhone через приватний фреймворк** — недокументований API: спершу окремий експеримент (spike) на
  iPhone користувача. Якщо не працює — iPhone не входить у v1, решта не блокується.
- Macs без батареї (iMac, Mac mini): розділ «Цей Mac» не показується, лише периферія.
- Іконка в рядку меню: символ батареї з кольором за найгіршим станом; в рядку меню опційно % заряду Mac (рішення Claude).

## Інтерфейс

Як у DiskHealth: вікно з висотою за вмістом, кнопки оновлення / налаштувань / закриття.
- Картка **«Цей Mac»**: заряд, здоров'я %, цикли, температура, стан заряджання, блок живлення.
- Картки **пристроїв**: назва, тип (іконка), заряд % (для AirPods — лівий/правий/кейс), час останнього оновлення.
- Деталі: усі показники + графіки здоров'я й циклів.

## Відкриті питання для виконавця

- Точні ключі `system_profiler` для різних пристроїв і як поводиться заряд AirPods, коли вони в кейсі.
- Чи потрібен `GameController` для Xbox, чи заряд уже є в `system_profiler` (перевірити з підключеним геймпадом).
- Структура модулів, вигляд карток — на розсуд виконавця в стилі DiskHealth.
